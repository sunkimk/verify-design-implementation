# 设计验收工作台

把**设计稿**和**开发做出来的截图**放在一起，一张一张比对，告诉你哪里做得和设计不一样，然后生成一份可以发给开发的清单。

原来你要做的事：两个窗口切来切去、放大缩小、量间距、截图圈红、写文档。
现在：把图丢进去，点一下，得到一份带图、带坐标、带修改要求的清单，可以导出成 PDF / 网页 / 图片发出去。

> 跟着下面走一遍，大概 10 分钟就能出第一份验收报告。
> 要改代码、改界面的说明在最后一节「[给开发者](#给开发者)」。

---

## 一、它能做什么、不能做什么

**它会给你什么**

| 你得到 | 长什么样 |
|---|---|
| 一份问题清单 | 每条写清「设计要求是什么」「现在做成什么样」「要改成什么」 |
| 每条都带图 | 自动在设计稿和截图上框出问题位置 |
| 优先级 | P0 必须改 / P1 应该改 / P2 可以改 |
| 可导出 | PDF、网页、图片、表格数据，文件名自动带时间，不会互相覆盖 |

**它不会做什么 —— 这点很重要**

- **AI 说"没发现问题"不等于验收通过。** 它是帮你先过一遍、别漏掉明显的差异，最终该不该通过是你说了算。
- 它不会改代码，也不会自动提 bug 单。
- 它看的是**静态的图**。动效、点击之后的跳转、加载状态这些，它看不到——你要自己截图成不同的"界面"再放进去比。

## 二、怎么装

### 最省事：跟 AI 说一句话

如果你在用 Claude Code，把下面这段**整段复制**发给它：

```
帮我装这个 Skill：把 https://github.com/sunkimk/verify-design-implementation
克隆到 ~/.claude/skills/verify-design-implementation（目录名保持不变），
装完确认里面有 SKILL.md，然后告诉我启动命令。
```

在用 Codex 的话，把路径换一下：

```
帮我装这个 Skill：把 https://github.com/sunkimk/verify-design-implementation
克隆到 ~/.codex/skills/verify-design-implementation（目录名保持不变），
装完确认里面有 SKILL.md，然后告诉我启动命令。
```

装完**重启一下** Claude Code / Codex，它就能认出这个 Skill 了 —— 之后你直接说「用设计验收工作台帮我比一下这几张图」就行，不用自己记命令。

### 或者自己贴一行命令

不想麻烦 AI，就在终端里贴这一行（Claude Code 用户）：

```bash
git clone https://github.com/sunkimk/verify-design-implementation.git ~/.claude/skills/verify-design-implementation
```

Codex 用户换成这行：

```bash
git clone https://github.com/sunkimk/verify-design-implementation.git ~/.codex/skills/verify-design-implementation
```

### 完全不想碰命令行

1. 在这个仓库页面点绿色的 **Code → Download ZIP**，下载后解压
2. 解压出来的文件夹**改名成 `verify-design-implementation`**（下载的 ZIP 会多带一个 `-main` 后缀，要去掉）
3. 把它拖进下面这个文件夹：
   - Claude Code：`~/.claude/skills/`
   - Codex：`~/.codex/skills/`

> 这两个文件夹是隐藏的，Finder 里按 `⌘ + ⇧ + G`，把路径粘进去回车就能打开；如果没有 `skills` 这个子文件夹，自己新建一个。

> ⚠️ **文件夹名字必须是 `verify-design-implementation`**，别改名，改了就认不出来。

### 只是想用工具，不打算当 Skill 用？

那放哪都行，随便找个地方 clone 或解压，然后看下一节自己启动。

## 三、第一次使用：准备两样东西

这两步只做一次，以后就不用管了。

### 1. 装 Node

去 [nodejs.org](https://nodejs.org) 下载安装（选带 **LTS** 字样的那个），一路下一步。
这是工具运行需要的底座，装完不需要做任何设置。

### 2. 装 Codex 并登录

Codex 是 OpenAI 的命令行工具，**AI 检测靠它**。

- 安装：照 [OpenAI Codex 官方说明](https://developers.openai.com/codex/) 走一遍
- 登录：装完在终端里执行一次 `codex login`，用你的 ChatGPT 账号登录

> ⚠️ **只装不登录是不行的。** 工具启动时会明确告诉你「AI 未连接」，界面能打开但点检测没反应。

**需要付费账号吗？** 需要。AI 检测消耗的是你 ChatGPT 账号的额度（Plus / Pro 都可以）。具体能跑多少，见下面「[AI 额度能跑多少](#九ai-额度能跑多少)」。

## 四、每次打开：两步

### 第 1 步：启动

**最省事的办法：跟 AI 说一句「打开设计验收工作台」**，Claude Code / Codex 会自己把服务起起来，并把网址给你。

想自己来也可以。打开「终端」（Mac 上按 `⌘ + 空格`，输入 Terminal 回车），按你装的位置贴一行：

```bash
# Claude Code 用户
node ~/.claude/skills/verify-design-implementation/scripts/start_workbench.mjs
```

```bash
# Codex 用户
node ~/.codex/skills/verify-design-implementation/scripts/start_workbench.mjs
```

放在别的地方了就把路径换掉。

> 小技巧：不用手打路径。在终端里先输入 `node ` 和一个空格，然后把 `scripts` 文件夹里的 `start_workbench.mjs` 文件**直接拖进终端窗口**，路径会自动补全。

### 第 2 步：打开网址

回车后终端会打印三行，像这样：

```
ZYMIX_WORKBENCH_URL=http://127.0.0.1:43127/
ZYMIX_STATUS=Codex bridge ready
ZYMIX_PROVIDERS=codex
```

**复制第一行等号后面那个网址**，粘到浏览器里打开，就是工作台。

三行分别是什么意思：

| 这一行 | 意思 |
|---|---|
| `ZYMIX_WORKBENCH_URL=...` | 工作台的网址，复制这个去浏览器打开 |
| `ZYMIX_STATUS=Codex bridge ready` | AI 已就绪。如果这里写的是没登录，先去执行 `codex login` |
| `ZYMIX_PROVIDERS=codex` | 用 Codex 做检测（只有登录成功才会出现这一行） |

> ⚠️ **必须用终端给的这个网址。** 直接去文件夹里双击 `workbench.html` 也能打开界面，但点检测会一直失败 —— 那个网址里带着一把一次性钥匙，AI 认这把钥匙。
>
> ⚠️ **终端窗口别关。** 关了就等于关掉了服务，浏览器里的页面会失去连接。用完再关。

## 五、跑通第一次走查（5 步）

### 第 1 步 · 把图放进去

点左上角的 **＋**（鼠标停上去会显示「添加设计稿或实现图」），弹出「走查素材」。

里面有两个框：

- **左边「设计稿」** —— 放设计给的图
- **右边「实现截图」** —— 放开发做出来的截图

每个框都支持三种放法，随便挑：

| 怎么放 | 操作 |
|---|---|
| 点选 | 点一下框，从文件夹里挑，**可以一次选很多张** |
| 拖进来 | 直接把图从文件夹拖到框里 |
| 粘贴 | 复制了图之后，点一下框，按 `⌘ + V`（Windows 是 `Ctrl + V`） |

设计稿框下面还有一个小按钮「**从 Figma 导入**」，可以直接填 Figma 链接把画板拉进来。

> 💡 **两边都放齐了才会进入下一步。** 只放了一边，它会提示你还缺哪一边。
> 💡 **文件名不用讲究。** 截图叫 `IMG_8823.PNG` 也没关系，它靠图片长相自己配对。

### 第 2 步 · 确认配对

放完图会弹出「**确认界面配对**」—— 它已经猜好了哪张设计稿对哪张截图，你只要核对一下。

上面有四个标签，**默认停在「待配对」**，因为那里放的就是它拿不准、需要你看一眼的那几组：

| 标签 | 里面是什么 |
|---|---|
| **待配对** | 它不太确定的，**需要你处理** |
| 已配对 | 它很确定的，也包括你手动指定的 |
| 已忽略 | 你标记了这轮不检测的 |
| 全部 | 所有组 |

每组可以做这些事：

| 想做什么 | 怎么做 |
|---|---|
| 看清楚是不是同一个界面 | 点「**对比预览**」，两张图并排放大看，看完关掉 |
| 换掉其中一张 | 点图下面的文件名下拉，重新选一张 |
| 确认这组没问题 | 点「**确认配对**」 |
| 这组这轮不检测 | 点「**忽略该组**」（之后可以在「已忽略」里恢复） |
| 补一组 | 点右上「**＋ 新增一组**」，再各自选图 |

> 💡 **同一张图可以选多次，这是正常的。** 比如安卓和 iOS 是同一个界面，用同一张设计稿对两张截图，直接选就行。
> 💡 长设计稿 + 多张连续滚动截图时，顶部会出现「自动去重拼接」的入口，可以把多张截图拼成一张长图再比。

核对完点右下角「**开始检测 N 组**」。

> 也可以点「仅导入图片」—— 只把图摆进工作台不花额度，之后再决定检测。
>
> 关掉这个弹窗（按 Esc 或点右上 ×）会**问你一次**，因为确认了就会丢掉这次导入的图；点「继续配对」就不会丢。

### 第 3 步 · 等它跑完

一组一组跑，每张图上会显示进度。底部有「中止」可以随时停下。

跑完之后，每一组的标题下面会写着这一组的状态：

| 状态 | 意思 |
|---|---|
| **待处理问题** | 查出差异了，去右边看清单 |
| **未发现未忽略问题（非人工验收通过）** | AI 没查出差异 —— 但这不等于验收通过，还要你自己看一眼 |
| **未检测** | 还没跑（或者被取消了） |
| **检测失败** | 没跑成功，看「[出问题了怎么办](#八出问题了怎么办)」 |
| **两侧不对应，需重新配对** | 这两张图不是同一个界面，换图重配 |

### 第 4 步 · 看问题清单

右边那一栏就是结果。每条问题长这样：

```
VD-001   P1   视觉                        复制剪贴板  忽略
按钮圆角比设计稿小

  [设计稿局部图]        [实现截图局部图]

  设计预期   圆角 12px，主色填充
  实现现状   圆角 4px，填充色偏浅
  复刻要求   圆角改为 12px，填充改为 #2453ED

  设计稿：x 24 · y 520 · 148×44px
```

**怎么读**

| 部分 | 意思 |
|---|---|
| `VD-001` | 问题编号，导出后开发按这个对。AI 查出来的是 `VD-`，你自己加的会额外带一个「人工新增」标签 |
| `P0` / `P1` / `P2` | P0 必须改、P1 应该改、P2 可以改 |
| 布局 / 内容 / 状态 / 视觉 / 可用性 | 问题属于哪一类，可以按这个筛 |
| 设计预期 | 设计稿里本来是什么样 |
| 实现现状 | 现在做成了什么样 |
| 复刻要求 | 要改成什么（这句是给开发看的） |
| 最下面一行坐标 | 问题在图上的位置，带 `实测` 字样的是量出来的，没带的是估的 |

**你可以改**

清单是给你改的，不是只能看：

| 想做什么 | 怎么做 |
|---|---|
| 改标题或描述 | 直接点上去改，标题最多两行 |
| 这条不算问题 | 点「**忽略**」（去「已忽略」标签里能恢复） |
| AI 漏了，我自己加一条 | 点清单右上「**＋ 新增**」，在图上拖出框，自己写 |
| 让 AI 帮我写这条 | 手动新增的问题卡上有「**AI 识别填写**」，它会看着你框的位置帮你写（会额外消耗一点额度） |
| 把一条发给开发 | 点「**复制剪贴板**」，文字带图一起复制 |
| 挪动或调整框的位置 | 直接拖框，或拖四个角 |

**画布上能做的事**（鼠标停在底部按钮上会显示快捷键）

| 想做什么 | 按钮 / 快捷键 |
|---|---|
| 看全部图 | 「适应画布」/ `F` |
| 放大缩小 | `+` / `-`，`0` 回到 100% |
| 拖动画布 | 按住 `空格` 键再拖 |
| 叠加对比（两张图重叠，拉透明度看差异） | 「叠加」/ `O` |
| 回到标注视图 | 「标注」/ `A` |
| 暂时隐藏所有红框 | 「隐藏选框」/ `H` |
| 收起右边清单，看大图 | `I` |

### 第 5 步 · 导出

点右下角「**导出**」，选一种格式：

| 格式 | 什么时候用 |
|---|---|
| **PDF** | 要打印、要发给不方便开网页的人 |
| **HTML（网页）** | 最好用。有目录能跳转，图片证据都在里面 |
| **图片（PNG）** | 要贴到群里、贴进 PPT。每组概览和每条问题各一张，打包成 ZIP |
| **Markdown** | 要粘到飞书 / Notion / 需求文档里 |
| **JSON** | 给开发或程序读的结构化数据（问题 + 坐标） |

然后选两件事：

- **导出范围**：只导当前这一组，还是全部组
- **文件组织**：合并成一份文件，还是每组一个文件打包成 ZIP

> 💡 文件名自动带日期时间，比如 `S01-wallet-design-合并报告_202609160002.html`，导多少次都不会覆盖上一份。
> 💡 被你忽略的问题不会导出去。

## 六、界面上各块是什么

| 位置 | 是什么 |
|---|---|
| 最上面一条 | 项目名、设计师名（点一下就能改）、任务历史 |
| 左边一竖排图标 | 走查素材（`U`）、任务历史（`L`） |
| 中间大片区域 | 画布。每一组是一个"界面"，左边设计稿、右边截图 |
| 底部一排按钮 | 撤销、保存记录、开始验收、视图切换、缩放 |
| 右边一栏 | 问题清单 / 已忽略、新增、筛选、导出 |
| 顶部中间偶尔冒出来的小条 | 提示消息（成功、失败都在这里说，3 秒自己消失；失败的要你手动关） |

> 组数多的时候，鼠标移到某一组上，组上会浮出一排小图标：更换设计稿、更换实现图、只跑这一组、删除这一组。

## 七、做完了怎么保存，下次怎么复查

### 保存这一轮

点底部的保存图标（`⌘ + S`）。它会存在**你自己的浏览器里**，不上传任何地方。

保存的是整个现场：图、问题清单、你改过的文字、你忽略掉的那些，全都在。

### 回到之前那一轮

点「任务历史」（左边竖排图标，或按 `L`），里面是你保存过的记录。**点一下某条记录，就回到当时的现场** —— 图、问题、忽略状态原样恢复，可以接着改、接着导出。

记录右边有删除按钮，不要的可以删掉。

### 开发改完了，怎么验第二轮

现在的做法是这样：

1. 点「任务历史」，点开上一轮那条记录（回到当时的现场）
2. 鼠标移到某一组上，组上会出现一排小图标，点「**更换实现图**」那个，选开发新给的截图
3. 再点同一排里的「**开始验收当前组**」，只重跑这一组

这样一组一组换、一组一组跑，额度也省。

> ⚠️ **说明一下：** 工具里已经写好了一套"自动对比两轮"的功能（能把每条问题标成 **已修复 / 仍存在 / 新增**），但**目前界面上没有入口可以点到它**，所以上面这个换图重跑的办法是现在唯一可行的做法。第二轮和第一轮的对比暂时得你自己看。

## 八、出问题了怎么办

顶上冒出红条的时候，对照这张表：

| 提示写的是 | 真正的意思 | 你该做什么 |
|---|---|---|
| **Codex 账号额度已用完** | 你 ChatGPT 账号的额度用光了 | 等额度恢复或者充值。**重试没用**，工具会自动停下并取消还在排队的组，不会一个个白试 |
| **Codex 未登录或凭据失效** | 登录过期了 | 终端里重新 `codex login`，回来点「重试本屏」 |
| **两侧不是同一个界面** | 这两张图配错了 | 换掉其中一张，或者重新配对。这种情况重试没意义，工具也不会给你重试按钮 |
| **模型这次没能处理这组图** | 图太大或服务忙 | 点「重试本屏」，一般就过了 |
| **返回结果无法解析** | AI 这次回答不完整 | 点「重试本屏」 |
| **检测未完成** | 其他原因 | 把鼠标停在提示上能看到英文原文，点「重试本屏」 |

几个说明：

- **同一个错误只提示一次。** 你点了重试还是同样的错，它不会再弹一遍来烦你。
- **AI 没跑通不影响你手动走查。** 那一屏照样可以用「＋ 新增」自己记问题，导出也照样带上。清单顶上那条红提示可以直接关掉。
- 提示里都是中文。英文原文放在鼠标悬停的浮层里，需要时才看。

## 九、AI 额度能跑多少

### 先搞清怎么算

工具本身不收费，花的是你 ChatGPT 账号的额度。算法很简单：

| 你做的动作 | 消耗 |
|---|---|
| 检测 **1 组**（1 张设计稿 + 1 张截图） | **1 次请求** |
| 检测 10 组 | 10 次请求 |
| 点「重试本屏」 | 再 1 次 |
| 点某条问题上的「AI 识别填写」 | 再 1 次 |
| 第二轮再跑 10 组 | 10 次请求 |
| **导入图片、看图、改文字、忽略、手动新增、导出** | **0 次，完全不花** |
| 配对页里点「仅导入图片」 | **0 次** |

每次请求会带上 2 张图（设计稿 + 截图），工具会先把图压到最长边 720 / 1440 以内再发，所以你放 @3x 的大图也不会额外多花。

### 换算到 ChatGPT Plus

OpenAI 给 Plus 的官方口径是：**每个滚动的 5 小时窗口大约 10～100 次**智能体请求，另外还有一个每周总量的上限（2026 年 8 月起 Plus 恢复了 5 小时窗口，Pro 目前不受 5 小时限制）。区间给得很宽，因为每次请求的轻重差别很大。

按「1 组 = 1 次请求」折算：

| 套餐 | 5 小时窗口大概能检测 | 换成实际工作量 |
|---|---|---|
| **Plus**（保守估计） | **约 10 组** | 一个功能模块（登录、下单流程这种）差不多够跑完一遍 |
| **Plus**（宽松估计） | **约 100 组** | 一个中型 App 的主要界面能过一轮 |
| **Pro 5x** | 约 50～500 组 | 一整个版本的全量走查 |
| **Pro 20x** | 约 200～2000 组 | 基本不用算 |

> ⚠️ **这只是估算，别当准数。** 本工具的一次请求要读 2 张图并产出结构化清单，属于偏重的请求，所以**实际更接近区间的低端**（Plus 一个窗口十几到几十组比较现实）。
>
> **想知道你自己的真实数字，最靠谱的办法是测一次**：先放 5 组跑一遍，看额度掉了多少，往上乘就行。

### 查自己还剩多少

- 在 Codex 命令行里输入 `/status`
- 或者去 Codex 设置里的 Usage 页面看

额度用完之后，可以等窗口恢复，也可以单独买额度包（Plus 和 Pro 都能买，不用升级套餐）。

### 省额度的几个习惯

1. **一次多放几组，攒着一起跑。** 请求数只跟组数有关，跟你分几次点无关，但一起跑你只用等一次。
2. **配对页里先把明显不用检测的组「忽略该组」。** 被忽略的组不发请求。
3. **同一组别反复重试。** 如果是额度或配对的问题，重试只是白烧。
4. **手动记录不花钱。** 你自己一眼能看出来的问题，直接「＋ 新增」写上，比让 AI 跑一遍划算。
5. **第二轮只挑改过的界面。** 不用整批重跑，可以只对需要复查的那几组做。

## 十一、常见疑问

**Q：一定要用终端吗？看着有点怕。**
就粘一行、按一次回车，之后所有操作都在浏览器里点。这一行的作用只是"把服务打开"。

**Q：能不装 Codex 只看界面吗？**
可以。界面照样打开，图照样放进去，可以手动记问题、导出报告 —— 只有「AI 检测」这一项不能用。

**Q：一次最多放多少张图？**
没有硬限制，二十几组也能跑。图多的时候配对页会自动把要你确认的几组排在前面。

**Q：设计稿和截图尺寸不一样怎么办？**
没关系，工具会按比例对齐，坐标也会换算成逻辑尺寸（比如 @3x 图会同时给出 pt 值）。

**Q：AI 说没问题，我就能通过了吗？**
不能。这是 AI 的结论，不是验收结论。界面上也会这么写 —— 请你自己再过一眼。

**Q：换电脑了怎么办？**
按「[怎么装](#二怎么装)」重新装一份就行。但**走查记录存在原来那台电脑的浏览器里，不会跟着走** —— 重要的记录记得先导出成文件带走。

**Q：端口被占用了怎么办？**
默认用 43127，被占用会自动换一个空闲端口，照样看终端打印的那行网址就行。

## 给开发者

这个目录本身就是一个 Skill，目录名必须是 `verify-design-implementation`（要和 `SKILL.md` 里的 `name` 一致）。

**作为 Skill 安装**

| 场景 | 放哪 |
|---|---|
| Claude Code，个人 | `~/.claude/skills/verify-design-implementation/` |
| Claude Code，跟着某个仓库走 | 该仓库的 `.claude/skills/verify-design-implementation/` |
| Codex，个人 | `~/.codex/skills/verify-design-implementation/` |
| Codex，跟着某个仓库走 | 该仓库的 `.codex/skills/verify-design-implementation/` |

两边认的都是目录里的 `SKILL.md`（`name` + `description`）。`agents/openai.yaml` 是 Codex 侧额外的入口清单，其他 agent 会忽略它。装完要重启会话才会被扫到。

**前置条件**

| | 需要什么 |
|---|---|
| 打开工作台 | 只要 **Node 18+**。不需要 `npm install` |
| 跑 AI 检测 | **已登录的 Codex 命令行**。不需要 API key。装了但没登录不算，启动时会明确指出 |
| `scripts/visual_diff.py` | Python 3 + `pip install -r requirements.txt`（opencv / numpy / pillow） |
| 改界面 | 在 `assets/shadcn-review-app/` 里 `npm install` |

`scripts/validate_acceptance_report.py` 只用标准库。

**用哪个模型**

只调用 **Codex**，用它当前的默认模型。不指定模型、不读 API key。

- **在 Claude Code 里跑这个 Skill 也一样走 Codex**，不跟随启动环境
- Codex 没登录：页面照样打开，状态显示「AI 未连接」，`/api/health` 返回 503

不再支持 Claude 命令行。Claude CLI 没有原生图片输入参数，只能让模型自己去调 `Read` 读取图片路径，无法保证完整图片真的进入上下文——对逐像素级的设计走查来说不可靠，因此这条路径已移除。

**环境变量**

| 变量 | 作用 |
|---|---|
| `ZYMIX_PORT` | 指定端口。不指定时默认 43127，被占用会自动换一个空闲端口 |
| `CODEX_BIN` | Codex 不在 PATH 上时指定可执行文件路径 |

`ZYMIX_PROVIDER` 已废弃；设成 `codex` 以外的值会直接报错退出。

**改界面**

```bash
cd assets/shadcn-review-app
npm install
npm run dev     # 开发
npm run build   # 重新生成 workbench.html
```

`npm run build` 先由 Vite 产出 `dist/`（可丢弃的中间产物），再把全部资源内联成单文件 `assets/shadcn-review-app/workbench.html`——也就是 bridge 实际服务的那个文件。构建产物全部落在包内。

**改完界面一定要提交重新生成的 `workbench.html`**，否则别的机器拉下来看到的还是旧界面。

组件和 token 基线是 shadcn 预设 `bKsFBxgG`（base-luma / Stone / Blue / Inter / Lucide）。

改动之前先读 `CLAUDE.md`，提交之前走 `docs/VALIDATION_CHECKLIST.md`。
