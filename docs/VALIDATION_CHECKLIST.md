# 修改后的强制回归清单

按改动选择相关章节。文档调整检查链接与契约；UI调整构建并验证受影响交互；归一化、框选、导出或Bridge改动增加对应的回归用例。已通过的检查不因流程要求重复执行；无新增风险时停止。

## A. 构建与启动

- [ ] `npm install` 成功。
- [ ] `npm run build` 成功，且没有在包外面写出任何文件。
- [ ] 不装 `node_modules` 时 `node scripts/start_workbench.mjs` 仍能启动并打开页面。
- [ ] 端口被占用时会自动换端口，不会抛出 EADDRINUSE 栈。
- [ ] `ZYMIX_PROVIDERS` 只在 Codex 已登录时列出 `codex`，`ZYMIX_STATUS` 与实际调用的一致。
- [ ] **在 Claude Code 会话里启动也调用 Codex**，不因启动环境切换 provider。
- [ ] Codex 装了但未登录时不被当作可用，并给出 `codex login` 提示。
- [ ] Codex 未登录时页面仍可打开且 `/api/health` 返回 503、显示“AI 未连接”。
- [ ] `ZYMIX_PROVIDER` 设成 `codex` 以外的值时直接报错退出。
- [ ] AI 调用失败时状态栏显示 Codex 的真实原因，不是裸的“退出码 1”。
- [ ] 启动器和工作台里没有任何 Claude CLI 调用路径残留。
- [ ] `workbench.html` 已重新生成，打开后不是空白页。
- [ ] 通过 `node scripts/start_workbench.mjs` 打开的页面显示“AI 已连接”。
- [ ] 关闭页面再重新打开同一个 HTTP URL，连接状态仍正常。

- [ ] 画布铺满窗口并带点阵底纹，两侧面板浮于其上。

- [ ] 左侧工具栏常驻不可收起、垂直居中；hover「＋」展开素材面板，hover「历史」展开走查记录。

- [ ] 画布底纹随缩放同比变化，并随平移一起移动。
- [ ] 界面以顶部标签展示，点击可跳转到对应界面。

- [ ] 记录被修改后，画布工具条出现「撤销修改 / 保存到记录」；撤销回到存档内容，保存写回**同一条记录**不新增。

- [ ] 素材弹窗**没有「上传 / Figma」两个 tab**；设计稿与实现截图两个投放区常驻并排。

## B2. 批量走查

- [ ] 可一次选中多张设计稿和多张实现截图。
- [ ] 截图命名为 `IMG_xxxx` 且上传顺序与设计稿不一致时，仍能正确配对。
- [ ] **只选了一侧时不弹配对确认页**，素材栏保持可操作并提示还缺哪一侧。
- [ ] 两侧都选齐后才弹出配对确认页。
- [ ] **全部自动配对成功时，配对页默认落在「已配对」并直接显示所有组**，不是空的「待配对 0」。
- [ ] 存在不匹配/待确认项时仍默认落在「待配对」，且只显示需要处理的那几组。
- [ ] 手动切过标签后，自动回落不再改动选择；把所选标签里最后一项处理掉也不会被弹到别的标签。
- [ ] **上一次导入停在「全部」或「已配对」（例如点过「＋ 新增一组」）后，下一次导入仍从「待配对」开始**，不沿用上次的标签。
- [ ] 空工作台顶栏显示「项目：未命名项目」，不显示 `design` 之类看起来像真实数据的占位名。
- [ ] 配对结果在检测开始前先出确认页，可逐条改配。
- [ ] 确认页内可直接重选设计稿或截图，数量对不上时不必取消重来。
- [ ] **同一张截图可以被多个设计稿选中**（同一界面的 iOS/Android 版本要与同一份设计稿分别对比，
      或一张实现截图要对照两个设计稿版本）；手动选择不会把它从别的组里抢走。
- [ ] 自动配对仍然优先用没被占用的截图；只有显式选择才允许重复。
- [ ] 置信度反映与次优候选的差距，配对正确时不会普遍显示为低。
- [ ] **两侧根本不是同一个界面时标为「不匹配」并给出原因，绝不显示为「高」**
      （仅靠与次优候选的差距判定会漏掉这种情况：所有候选都错时，其中一个仍可能领先很多）。
- [ ] 宽高比差异大（如 400×400 对 750×1624）会被判为不匹配并写明两侧尺寸。
- [ ] 真实成对的界面不会被误报为不匹配。
- [ ] 确认页有「设计稿 / 配对 / 实现截图」列头，缩略图等高显示并标注各自像素尺寸。
- [ ] 设计稿文件名的自然序（01-、02-）决定界面顺序与 S01/S02 编号。
- [ ] 不成对的界面被跳过，不进入检测。
- [ ] 批量检测串行执行，先完成的界面立即可查看和编辑。
- [ ] 单个界面失败时其余界面不受影响，并可单独重试。
- [ ] 批量检测可中止。
- [ ] 切换界面后，问题清单、标注和已忽略记录都随该界面独立切换。
- [ ] 在一个界面上编辑问题文案，切走再切回内容保留，且不影响其他界面。

## B2b. 长图设计稿 × 多张滚动截图

- [ ] 1 张长图设计稿 + 多张同尺寸连续截图时，配对确认页顶部出现「自动去重拼接」入口，
      并说明设计稿高度、单张截图高度以及直接配对会丢下几张。
- [ ] 不满足条件时不出现该入口（多张设计稿、截图尺寸不一致、设计稿不比截图明显更高）。
- [ ] **状态栏与固定 tabbar 被识别为固定区域**，只在拼接结果里各保留一份。
- [ ] 重叠量是实测的：连续截图滚动距离不等时，各接缝的重叠像素各不相同且正确。
- [ ] 用同一长页切出的**非相邻**两张截图不会被当成可拼接（均值差很低但逐行匹配率只有一半左右）。
- [ ] 截图顺序打乱、中间漏截一屏、尺寸不一致时都拒绝拼接，写明是第几张与第几张之间的问题，
      且**原截图不被改动**（可以修正后重试）。
- [ ] 拼接结果与原长图逐像素一致（用同一长页切片可验证：差异像素数应为 0）。
- [ ] 拼接后自动与设计稿按相同比例切成约一屏高的分段，两侧段高一致且合计等于整页高度。
- [ ] **接缝落在整行背景色的卡片间隙里**，不会从卡片或文字中间切开
      （只按「最平滑的一行」选会切进大卡片内部，因为卡片内部比间隙更平滑）。
- [ ] 分段配对被固定为按顺序一一对应，不交给结构匹配重新推断。
- [ ] 分段后仍需确认才开始检测，不会直接花掉 N 次模型调用。
- [ ] 提示里写清拼了几张、去重多少像素、各接缝重叠多少、切成几段。
- [ ] 设计稿与实现图完全一致时，逐段检测的结果为 0 个问题（无误报）。

## B4. 问题清单空状态（八种必须各不相同）

- [ ] **全新任务不上传任何图，展开问题清单时绝不出现“已完成检测”“没有发现问题”之类的成功文案**
      （旧版会走到 `is-clean` 分支，显示绿色「这一屏没有发现问题 / 已完成检测，未发现与设计稿的差异」）。
- [ ] 未导入：提示还没有导入素材，并说明「这里为空是因为还没有素材，不代表没有问题」。
- [ ] 素材未配齐：只选了一侧时说明已选几张设计稿、几张截图，以及还缺哪一侧。
- [ ] 恢复中：解码记录截图期间显示「正在恢复走查现场」，不显示成功或零问题。
- [ ] 未检测：两侧齐了但没跑，提示去点「开始验收」或按 R。
- [ ] 检测中：显示正在检测本屏。
- [ ] 检测失败：给出失败分类与原因，可重试的才出现「重试本屏」。
- [ ] 配对阻塞：见下节。
- [ ] 检测通过零差异：文案写明这是 AI 结论、不等于验收通过，需要人工再确认。
- [ ] 检测成功后替换任一侧图片，结论立即回到「未检测」，不保留旧的通过结论。

## B5. 配对阻塞（AI 拒绝比对）

- [ ] 两侧不是同一界面/同一状态时，AI 只返回一条 `kind=blocker`，**不再输出一串视觉差异**。
- [ ] 该条不计入「问题项 N」、类型筛选、优先级筛选、底部「共 N 项问题」和画布标注。
- [ ] 导出 HTML / PDF 被禁用，阻塞项**不会作为研发缺陷导出**。
- [ ] 不显示夸夸卡片。
- [ ] 提供「更换实现截图」，多屏时提供「在总览里重新配对」。
- [ ] 「确认是实现错误」可由人工升级为 P0 缺陷，可撤销；系统不会自动升级。
- [ ] 总览与标签条显示「配对阻塞」，整体结论保持「验收未完成」，不显示已通过。
- [ ] 归档后重新打开该记录，阻塞项仍按阻塞处理；**旧版记录（没有 blocker 字段）显示不变**。
- [ ] 改了 `scripts/start_workbench.mjs` 的提示词后**必须重启服务**再验证，否则跑的还是旧规则。

## B3. 界面总览与失败恢复

- [ ] 界面多于一屏时，标签条左端有「总览」入口，并显示「已检测 x/总数」。
- [ ] 标签条横向滚动时「总览」入口固定不动，不会随标签滑走。
- [ ] `G` 键可开关总览，`Esc` 可关闭。
- [ ] 总览首行是结论而不是问题数：任一界面处于未检测/检测中/失败时显示「验收未完成」。
- [ ] **零问题的未检测界面不显示为「已通过」**，标签条与总览都显示「未检测」。
- [ ] 失败界面在总览与标签条上都标为失败，不显示 0 项问题。
- [ ] 状态筛选（需处理 / 有阻塞 / 失败 / 未检测 / 已通过）计数与卡片一致，数量为 0 的筛选项不出现。
- [ ] 点卡片跳到该界面并关闭总览，当前界面的卡片有选中描边。
- [ ] 结构不匹配的失败卡片显示「两侧不是同一个界面」并提供「换实现图」，不提供无意义的重试。
- [ ] 模型容量类失败显示「模型这次没能处理这组图」并提供「仅重试本屏」。
- [ ] 原始报错文本折叠在「技术详情」里，不占据卡片主视觉。
- [ ] 交换实现图后，被交换的两个界面都回到未检测且旧结果被清空，其余界面不受影响。
- [ ] 交换后没有任何一张图被丢弃（两张图各自落在一个界面上）。
- [ ] 「重试未完成 N 屏」只重跑失败与未检测的界面，且跳过结构不匹配的那些。
- [ ] **单屏重试不会新建一条只有 1 个界面的历史记录**，也不会重算复验对比。

## B6. 复验（跨轮次继承人工成果）

用独立夹具跑两轮即可验证：设计稿不变，第一轮实现图有 A、B 两个缺陷，第二轮修掉 A、保留 B、另加一个新缺陷。

- [ ] 复验从记录出发，自动带入设计稿，只要求补新截图；缺截图时问题栏显示「素材还没配齐」而不是成功文案。
- [ ] 复验横幅给出「已修复 / 仍存在 / 新增」，数字与夹具预期一致。
- [ ] **仍存在的问题保留上一轮人工改过的文案**（在第一轮改一条 expected 并「保存到走查记录」后复验验证）。
- [ ] **上一轮忽略过的问题在新一轮自动回到「已忽略」**，不需要再忽略一次。
- [ ] 自动回到已忽略的那一条**同样保留人工改过的文案**
      （只按「仍存在」匹配会漏掉它，因为它相对活动清单算「新增」）。
- [ ] 新一轮归档后重新打开该记录，活动问题与已忽略问题都与屏幕上一致
      （曾经归档的是 AI 原始报告，且 `ignoredIssues` 被写死为 `{}`，重开就丢人工成果）。
- [ ] 新一轮是**独立的新记录**并带 `reReviewOf` 指回上一轮；**上一轮记录内容完全不变**。
- [ ] 「保存到走查记录」写回同一条记录 id，不产生第二条。
- [ ] 在恢复的记录上点「开始验收」会先弹 Popconfirm；取消后问题、修改、归档记录数量都不变。

## C. 尺寸与等比归一

- [ ] 同尺寸图片正常比较。
- [ ] 不同像素尺寸但宽高比一致时，不创建尺寸问题。
- [ ] `750×1624` 与约 `591×1280` 可归一到 `375×812`。
- [ ] 缩放只使用一个统一因子；圆形、字体和卡片没有横向或纵向拉伸。
- [ ] 宽高比、页面状态或裁剪明显不兼容时，输出前置检查问题并停止伪比较。

## D. AI 检测质量

- [ ] `Football → 1234` 输出具体文案替换问题。
- [ ] `Travel ✈️ → 🧳` 输出独立图标问题。
- [ ] `Dancing → D22ancing` 不被大模块问题吞掉。
- [ ] 相同文字/图标没有因抗锯齿产生误报。
- [ ] 明显字号、字重、换行/截断差异能够被指出。
- [ ] 头图主体大小、位置和留白差异能够被指出。
- [ ] 重复商品卡片名称变化按模块合并，但列出每一条准确映射。
- [ ] 每条问题只有 P0、P1 或 P2；没有 P3 或“待确认”优先级。
- [ ] 每次检测同时执行 ZYMIX 文案规范检查。

## E. 加载状态

- [ ] 检测中画布只显示标题、一句说明、百分比。
- [ ] 页面中没有进度轨道、扫光、旋转、脉冲、装饰光晕或耗时脚注。
- [ ] 百分比使用 `role="progressbar"` 并更新 `aria-valuenow`。
- [ ] AI 阶段百分比持续推进，不长时间停在同一个数字；且始终小于 100%，不提前宣称完成。
- [ ] AI 阶段说明里给出预计耗时，不出现耗时计时器。

## F. 画布与框选

- [ ] 设计稿和开发稿同屏并排。
- [ ] 任一红框可从框内部整体拖动。
- [ ] 四角缩放可用，框不会越出原图。
- [ ] 调整设计稿框不会覆盖开发稿框，反之亦然。
- [ ] 调整后问题卡片缩略图立即同步。
- [ ] 20%–300% 缩放、百分比重置、拖动画布可用（下限从 50% 放宽，否则 @3x 手机双图无法“适应画布”）。
- [ ] 「适应画布（查看全图）」按钮与 `F` 键可用，能把两张图完整收进画布；空画布时禁用。
- [ ] **恢复历史记录后自动适应画布**，不再停在 100% 让两张图上下越界。
- [ ] 适应画布的缩放考虑左右浮动面板遮挡（按常驻图标条测量，不受 hover 浮层影响）。
